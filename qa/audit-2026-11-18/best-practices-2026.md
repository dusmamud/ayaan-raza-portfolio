## PageSpeed / Core Web Vitals
- PSI bands: 90-100 good, 50-89 needs improvement, 0-49 poor. Lab score is Lighthouse weighted avg; Google ranks on FIELD CWV, not lab score. Perfect 100 not expected.
- Field data = CrUX trailing 28 days; small/low-traffic site may show NO field data — then lab only.
- Lab cannot measure INP; TBT is lab proxy. Lab CLS only during load.
- Thresholds (75th percentile, mobile+desktop separately, all three must be Good): LCP ≤2.5s (poor >4s), INP ≤200ms (poor >500ms), CLS ≤0.1 (poor >0.25). INP replaced FID 12 Mar 2024. Claims LCP tightened to 2.0s unsupported.
- LCP fixes (invisible): LCP image in initial HTML, never lazy-load hero, fetchpriority=high (one per page), srcset/sizes 3-5 widths, AVIF>WebP>JPEG via picture, preload only if CSS/JS-injected, low TTFB via static+CDN.
- CLS fixes: width+height on every img/video (or aspect-ratio), reserve space for late-injected content, transform/opacity animations don't cause CLS. content-visibility:auto risky with reveal animations — don't apply blindly.
- INP fixes: break long tasks >50ms, scheduler.yield() with setTimeout fallback, less JS / route splitting / import() heavy widgets, minimal handlers. Do NOT remove cursor/magnetic/spotlight/hydration — design change, forbidden.
- Fonts: WOFF2 only, variable + subset + unicode-range, preload 1-2 faces ONLY with crossorigin even same-origin (else double download). font-display: swap + metric-matched fallback (size-adjust/ascent/descent overrides) is design-preserving; `optional` is visible change (fallback may persist) — owner decision. Keep swap.
- Render-blocking: CSS blocks paint; module scripts defer by default (SvelteKit output) so flags usually mean CSS/fonts/inline head scripts. Remove unused CSS/JS via Coverage; critical-CSS inlining risks FOUC — verify visually.
- Caching: hashed assets Cache-Control public max-age=31536000 immutable; HTML no-cache/revalidate; images/fonts long max-age only if URL changes with content. HTTP/2-3, correct MIME. Vary:Accept not needed for <picture>.

## Rich Results Test (Google)
- Answers eligibility ONLY, never display/indexing/ranking. Error = required missing/invalid or unparsable → ineligible. Warning = recommended missing → still eligible. "No items detected" = no Google-supported type found, not necessarily broken.
- Gallery = 25 features (Jun 2026). RETIRED: FAQPage rich result — limited Aug 2023 to gov/health, STOPPED for everyone 7 May 2026, docs removed 15 Jun 2026. Keep visible FAQ + markup (no removal); expect ZERO Google display. HowTo removed Sep 2023. Sitelinks search box (WebSite+SearchAction) removal from 21 Nov 2024 — inert/harmless; keep WebSite name/url for Site Names (homepage only). Breadcrumbs desktop-only since Jan 2025 (mobile shows domain only) — keep markup.
- Structured data NOT required for generative AI search; no special schema needed (Google Jul 2026). llms.txt not needed for Google Search.
- General policies: JSON-LD recommended; don't mark up invisible content; markup must match visible page; fake reviews/impersonation → manual action (loses rich eligibility); images must be crawlable/indexable.
- Article/BlogPosting (verified): NO required properties. Recommended (7): headline, image, datePublished, dateModified, author, author.name, author.url. image: representative, not logo/caption; ≥50K pixels, ideally 16x9+4x3+1x1. "1200px min" claims are NOT in Google doc. Dates ISO 8601 + timezone recommended. author: all authors, name-only in author.name, Person + url/sameAs to profile page. publisher NOT in Google supported table — absence is NOT an error/warning (harmless to add, valid schema.org).
- BreadcrumbList: ≥2 ListItems; position integer from 1; name; item URL (may omit item on last; name not required if item is Thing with name). Trail = typical user path, not URL mirror. Blockers: single item, bad position, relative/broken URLs, mismatch with visible breadcrumbs.
- ProfilePage+Person (verified): for creator/"About Me" pages — correct home is /about, NOT homepage/every page. Required: ProfilePage.mainEntity (Person/Org) + name. Recommended: dateCreated/dateModified; Person: alternateName, description, identifier, image, sameAs, interactionStatistic (hosting-platform stats only). image: no default/placeholder if none. sameAs: only real controlled profiles. Bare Person has NO standalone rich result — "Person not detected" in RRT is NOT a failure.
- WebSite/Organization: WebSite name+url homepage only → Site Names. Organization no required props (secondary source).

## Schema.org validator (validator.schema.org)
- Checks ALL schema.org types vs vocabulary (v30.1, Sep 2026); NO Google feature warnings; says nothing about eligibility. Both tools needed; neither alone sufficient.
- Errors (consensus): invalid JSON (whole block skipped), missing @context/@type, unknown/misspelled type/property, property not on type, wrong value type, non-ISO dates, empty values. Warning severity labels vary across explainers — report validator's literal wording, don't re-label from memory.
- schema.org defines almost NO formally required properties; "required" in reports usually = Google-required or structurally necessary. Person: name. FAQPage: mainEntity ≥1 Question, each name + acceptedAnswer (Answer.text); one block per page; site-authored + visible. BlogPosting: no required; meaningful min headline/image/dates/author. BreadcrumbList: itemListElement + position ordering.
- @id: one stable absolute @id for canonical Person/Org, reference it from author/publisher/mainEntity (Google example uses fragment #main-author within page; cross-page use absolute URLs). @context always https://schema.org. Multiple blocks or @graph both fine. URLs absolute canonical HTTPS everywhere. Dates ISO 8601 + timezone; datePublished immutable; dateModified = substantive change only, never build time; visible date must match structured date; no future dates. image: absolute/crawlable/representative, ImageObject or URL array; never logo/placeholder. author/publisher: objects with name (+url/sameAs), never bare strings; don't invent a company.

## Under-the-hood SEO/a11y (no visual change)
- Alt (WCAG 2.2 SC 1.1.1 Level A): decorative → alt="" (present, empty); informative/content (project screenshots, content illustrations) → concise contextual description, no "image of", no keyword stuffing, ~125 chars practical guideline not WCAG rule; functional (icon button/linked logo) → alt/aria-label = function/destination. Missing alt = filename read aloud. Google: alt most important image metadata; indexes <img> in <picture>; not CSS images.
- OG (ogp.me, 4 required: og:title, og:type, og:image, og:url): image 1200x630 (1.91:1) JPG/PNG <1MB aim; absolute HTTPS; declare og:image:width/height; og:image:alt describes image not caption. og:type one value: website for home/sections, ARTICLE for blog posts → unlocks article:published_time/modified_time/author(profile URL, not name)/section/tag; article:* ignored unless type=article. Twitter: X reads twitter:* then falls back to OG; with full OG only twitter:card needed (summary_large_image). Do NOT serve AVIF/WebP as og:image; keep PNG/JPG. X card docs archived — verify in validator.
- Canonical: self-referencing absolute HTTPS on every page; sitemap/canonical/internal links agree on one URL form. Don't use robots.txt/noindex to choose canonical.
- Robots/noindex: robots.txt ≠ exclusion (blocked URL can still be indexed). Correct: crawlable + meta robots noindex (+ X-Robots-Tag for non-HTML), EXCLUDED from sitemap. Internal search pages should be noindex (no search value, wastes crawl budget); check /search + ?q= variants.
- Sitemap: only canonical indexable URLs, absolute, UTF-8. Google IGNORES priority/changefreq — omit. lastmod used only if consistently accurate = last SIGNIFICANT change; frozen/shared lastmod or per-deploy bumps teach Google to ignore it; must agree with dateModified.
- Title/meta: NO Google character limit; 50-60 / 120-160 are tool rules of thumb (pixel truncation), report as truncation risk not violation. Snippets built from content; meta desc used when more accurate; rewrites frequent. Requirements: UNIQUE description per page; important words first.
- Placeholder # links: href="#" = empty fragment → scrolls top, appends #; flagged by Lighthouse crawlable-anchors + axe href-no-hash; violates WCAG 2.4.4 spirit; icon-only # links with no name announced as bare "link". Design-preserving fixes: real href if destination exists; <button> styled identically if action; aria-label for icon-only; real fragment links must point at existing id. OWNER DECISION for demo social links: keep # (accept flags) / identical button (does nothing, questionable) / real URLs. Do NOT invent URLs, do NOT remove icons.
- Other a11y: one h1/page, heading order, discernible names, labelled fields, lang, skip link, contrast AA 4.5:1 / 3:1 large. Contrast fixes = colour changes = design changes → flag for owner approval with exact token.

## Priority (design-preserving)
1. Errors: unparsable JSON-LD, missing Google-required (ProfilePage mainEntity/name, breadcrumb minimums), broken canonicals, robots-blocked noindex, missing alt attributes, dangling fragments.
2. LCP/CLS: hero eager+fetchpriority, srcset/sizes, width/height, font preload+matched fallback, immutable hashed caching + HTML no-cache.
3. Warnings: Article image ratios, author.url, ProfilePage recommended, og:image:alt/dimensions, og:type article + article:*, accurate lastmod/dateModified.
4. Owner decisions: font-display optional vs swap, demo # socials, contrast/colour, removing inert SearchAction/FAQPage (harmless; default KEEP per no-removal).
